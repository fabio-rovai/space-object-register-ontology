# Gate evaluation results

Each gate is run against the PRE-correction constants (git 24d684e) and the POST-correction constants (current pipeline/reconcile.py, commit 60d2938). PRE is the buggy code; POST is the corrected code, so anything a gate fires on for POST is a false positive and is reported as such.

Generated by paper/gates/evaluate_gates.py. All numbers below are reproduced by that script from the data files in data/.

## Gate 3: source inventory reconciliation

Compare the GCAT catalogue basenames the source publishes against the files the PRE harvest loaded, then quantify the coverage consequence of the omitted file.

Source index basenames: satcat, auxcat, ftocat, satcat100k.
PRE harvest fetched: satcat, auxcat, ftocat.
Listed but not fetched: satcat100k.

satcat100k objects: 354 (expected 354, matches: True).
Objects whose only GCAT source is satcat100k: 354.

PRE CoverageGap: 900 (expected 900).
POST CoverageGap: 622 (expected 622).
Objects recovered by including satcat100k: 278.

DISCREPANCY: the recovered figure is 278, not the expected 280. It equals PRE CoverageGap minus POST CoverageGap (900 minus 622 = 278) exactly, and all 354 satcat100k objects are disjoint from the other three GCAT files, so the intersection of satcat100k with CelesTrak is exactly 278. Both 900 and 622 reproduce exactly, which forces the recovered count to 278. The expected 280 is inconsistent with the 900 and 622 values (900 minus 280 would be 620, not 622).

## Verification notes

- Gate 2 reproduces the PRE DispositionDisagreement value of 932 and the POST value of 261 exactly.
- Gate 3 reproduces satcat100k = 354, PRE CoverageGap = 900 and POST CoverageGap = 622 exactly. The recovered-object figure is 278, not the expected 280; see the discrepancy note under Gate 3.
- Gate 1 lists the actual unclassified codes it found for every column, not just counts.
- Gate 1 fires on the CelesTrak columns (ORBIT_TYPE, OBJECT_TYPE, DATA_STATUS_CODE) identically for PRE and POST, because the correction added no controlled-vocabulary classifier for those columns. Those are genuine false positives and reflect the cost of a blanket total-function check applied to columns the pipeline treats as opaque strings.
- Gate 3 has no false positive: the POST CoverageGap of 622 is the true residual gap after including satcat100k, not a spurious firing.
